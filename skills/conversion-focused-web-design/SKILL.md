# Conversion-focused web design

Choose the mode from the requested outcome. If several apply, start with the requested deliverable and use the others only where they support it. Execute implementation requests in the existing stack. For a review, return findings before proposing a replacement.

## Establish the brief

Identify the audience, entry source, job they came to do, primary action and observable business outcome. Inspect the current route, components, brand assets and available evidence. Record which claims the business can substantiate. If evidence is missing, label assumptions and proceed with reversible work. Use fixtures or staging for submissions.

## Operating modes

| Mode | Work sequence | Deliverable |
| --- | --- | --- |
| Build | Sketch the decision sequence with real copy. Choose a focal point, compose the narrow layout, then implement wide layout and all action states. Follow a visitor from entry to confirmation. | Working page or requested prototype, action destination, QA results and measurement contract. |
| Audit | Specify route, entry source and task. Walk it on mobile, desktop and keyboard. Capture reproducible evidence. Score the rubric and rank defects by impact on the task. | For each priority give location, observed behavior, affected visitors, fix and acceptance check. Mark inaccessible states unknown. |
| Redesign | Capture baseline screenshots, brand cues, URLs, integrations, analytics and working paths. State what must survive. Change the smallest coherent part that resolves the problem. | Implemented changes, before/after rationale, parity checks for deep links, forms, tracking, responsive states and a rollback point. |
| Optimize | Define the funnel and validate counts. Combine behavioral data with direct evidence. Rank explanations, select one intervention, choose a feasible evaluation design. | Baseline with denominator, research-backed hypothesis, primary metric, guardrails, test or low-volume plan and decision rule. |

## Finish with evidence

For implementation, use the project's normal build and browser checks. For reviews, distinguish rendered behavior, source inspection, analytics and inference. Report the tested route and conditions, the highest-impact remaining uncertainty and exactly how to verify it. Treat a rubric improvement as a design assessment. Claim conversion lift only when the outcome data warrants it.
